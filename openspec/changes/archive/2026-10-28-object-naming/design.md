# Design

## Context

Implementation: `impls/rust` (`constraint_runtime` core, `sketch_ui` egui front-end). See proposal.md for motivation and the spec for required behavior.

Relevant current state:

- `Document` stores geometries in `IdMap<GeometryId, GeometryInst>` and constraints in `IdMap<ConstraintId, ConstraintEntry>`. Within a session ids are never reused; a future load path compacts them to `0..n`. Ids are therefore not stable across files, and names need their own storage.
- `GeometryInst` / `GeometryShell` are `Copy + Hash` and are read on the solve path. They must not carry a `String`.
- `remove_geometry` silently drops all constraints that reference the geometry (`retain`) and returns `bool`. So does `remove_constraint`.
- The capability-based factories by id (`Document::start_expr`, `direction_expr`, …) already return `None` when a capability is missing. Address resolution builds on them.
- Only Jacobian and residual evaluation are covered by the alloc-free tests. Structural edits may allocate.

## Goals / Non-Goals

**Goals:**

- Names in `Document`, consistent through every structural edit, with O(1) lookup in both directions and O(log n) auto-naming.
- Existing callers of `add_geometry` / `add_constraint` (about 160 call sites, mostly tests) stay unchanged: auto-naming happens inside them.
- Address parsing and printing without new dependencies.

**Non-Goals:**

- Undoable rename, command errors (#32/#33). `Document::rename` is a plain structural operation.
- Creating an object with an explicit name. The future load path (#8) uses add + rename.

## Decisions

### D1: Separate `Names` table owned by `Document`

New module `src/names.rs`, with tests in `src/tests_names.rs`:

```rust
pub enum ObjectId { Geometry(GeometryId), Constraint(ConstraintId) }

pub struct Names {
    by_name: HashMap<String, ObjectId>,
    geometry: IdMap<GeometryId, String>,
    constraint: IdMap<ConstraintId, String>,
    /// stem -> numbers in use with that stem (see D3)
    numbers: HashMap<String, BTreeSet<u64>>,
}
```

`Document` gets a private `names: Names` field. Every mutation that adds or removes objects updates it in the same method, so the table cannot drift. Because `Document: Clone`, snapshots (#29) include names for free.

- *Alternative:* a `String` in `GeometryShell` / `ConstraintEntry`. That breaks `Copy` on the solve-path type and gives no name → id index.
- *Alternative:* names in the command session (#32). We do not do this: the cascade on geometry removal would have to be reconstructed outside `Document`, and #15 would depend on #32.

### D2: Prefixes are associated constants of the kinds

- `Geometry::NAME_PREFIX: &'static str` is required, with no default: `Segment` → `"seg"`, `Arc` → `"arc"`.
- `ConstraintKind::NAME_PREFIX`: `Congruence` → `"join"`, `VectorsParallel` → `"par"`, `VectorsOrthogonal` → `"orth"`, `FixPoint` → `"fix"`, `EqualLength` → `"eqlen"`.
- `GeometryKind::name_prefix()` (via `with_kind!`) and `ConstraintInst::name_prefix()` (generated by `constraint_catalog!`) give runtime access.

`Congruence` is named `join` after the user-facing tool and the domain meaning ("UI shared points desugar to congruence").

A test asserts that every prefix is a valid name, does not end in a digit, and is unique across all geometry and constraint kinds. Uniqueness is not required by the spec, but it keeps scripts readable.

This fits the per-kind slices (#24): the prefix lives with the kind.

### D3: Auto-naming via a stem → numbers index

Every name in the table is split into `(stem, number)` when it ends in a canonical decimal number: digits without a leading zero (`0` itself allowed) that fit in `u64`. Such names are entered in `numbers[stem]`. Names without such a suffix (`x_axis`, `seg01`) are not indexed.

The next automatic name for prefix `p` is `p{max + 1}` with `max = numbers[p].last()`, or `p1` if there is none. Taken together:

- user-chosen names like `seg7` count automatically;
- the result cannot collide, because `p{max+1}` is a canonical name greater than every indexed one, and a non-canonical spelling is a different string;
- nothing is stored besides the index, which is derived from the names, so undo and load need no counter.

If `max == u64::MAX` (a pathological user name), `checked_add` fails. The fallback is the smallest unused number from 1, which is allowed because names may be reused.

- *Alternative:* scan all names on each creation. That is O(n) per add and O(n²) to build a large document.

### D4: Document API

```rust
impl Document {
    pub fn name(&self, id: ObjectId) -> Option<&str>;
    pub fn geometry_name(&self, id: GeometryId) -> Option<&str>;    // convenience
    pub fn constraint_name(&self, id: ConstraintId) -> Option<&str>;
    pub fn lookup(&self, name: &str) -> Option<ObjectId>;
    pub fn rename(&mut self, id: ObjectId, new: &str) -> Result<(), NameError>;
    pub fn remove_geometry(&mut self, id) -> Option<Removal>;       // was bool
    pub fn remove_constraint(&mut self, id) -> Option<Removal>;     // was bool
}
pub enum NameError { Invalid, Taken, UnknownObject }
pub struct Removal { pub geometries: Vec<(GeometryId, String)>, pub constraints: Vec<(ConstraintId, String)> }
```

- `add_geometry` and `add_constraint` keep their signatures and assign the automatic name.
- `remove_geometry` collects the ids of the referencing constraints before the existing `retain` and drops their names.
- The four existing `assert!(doc.remove_*(..))` calls in tests become `.is_some()`.
- Renaming to the current name returns `Ok(())`.

`Removal` carries ids and names, so #32 can report either. `Option` replaces `bool` instead of adding a second method, which avoids two removal APIs.

### D5: Addresses: hand-written parser in `src/address.rs`

```rust
pub enum Address { Point(PointExpr), Vector(VecExpr), Length(LengthExpr) }
pub enum AddressError {
    Malformed,
    UnknownName(String),
    NotAGeometry(String),
    ParamOutOfRange(f64),
    MissingCapability { name: String, capability: &'static str },
}
impl Document {
    pub fn resolve_address(&self, s: &str) -> Result<Address, AddressError>;
    pub fn point_address(&self, e: &PointExpr) -> Option<String>;
    pub fn vec_address(&self, e: &VecExpr) -> Option<String>;
    pub fn length_address(&self, e: &LengthExpr) -> Option<String>;
}
```

Grammar: `name "." suffix` with `suffix = ident | ident "(" number ")"`. The number is parsed with `f64::from_str` and must be finite and in `[0, 1]`. Whitespace is not allowed. Resolution looks up the name, then calls the matching factory by id (`start_expr`, `on_curve_expr(id, Normalized(t))`, …). A `None` from the factory becomes `MissingCapability`. Its `capability` field is the capability name (`"endpoints"`, `"line"`, `"circular"`, `"curve"`).

Printing maps formula tags back to suffixes. `CurveParam::Uniform` and the heading/turn families have no address and return `None`. `t` is printed with `{}` (shortest round-trip `f64` formatting), so print → resolve gives an equal expression.

- *Alternative:* a parser crate (`nom`, `pest`). That is a dependency for a ten-production grammar.
- *Alternative:* an address type with its own AST. Not needed; resolving straight to expressions is what callers want. #32 can add an AST if it needs to report addresses before resolving them.

### D6: GUI status messages

`App::report` currently overwrites the status with a generic "OK — geometries=…". It gets the success message from the caller, so tools can say what happened:

- `Added seg3`
- `Join: seg1.end → pick second point`, then `Added join1 (seg1.end = seg2.start)`
- `Parallel: seg1 → pick second line`, then `Added par1 (seg1, seg2)`
- `Added fix1 (seg1.start)`

The failure path keeps its current message. Names come from `Document::geometry_name` / `constraint_name`, and points from `point_address`.

## Risks / Trade-offs

- [Names add allocation and hashing to `add_geometry` / `add_constraint`] → These are structural edits, not on the solve path; the alloc-free tests do not cover them. Verify with the existing solver bench (`--no-run`) and the alloc-free tests.
- [`remove_*` signature change] → Only 4 call sites (tests), and `sketch_ui` does not call them yet.
- [`seg01`-style names are not counted by auto-naming] → No collision is possible (D3). Documented in the rustdoc of `Names`.
- [Failed structural solve still leaves the constraint (#28), now also with its name] → Unchanged behavior; fixed by #32. The GUI message names the constraint, which makes the bug easier to see.

## Migration Plan

This is an internal API only. There is no persisted data yet, and a revert is enough for rollback.
